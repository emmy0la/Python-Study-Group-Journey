# How I Approach Learning 

One of the biggest lessons from this experience is that reading code is very different from writing code.

So, my approach has been simple:

1. Learn the concept.
2. Write the code myself.
3. Predict what the code should do.
4. Run it.
5. Experiment with different values.
6. Break things intentionally.
7. Read the error.
8. Fix the problem.
9. Apply the concept to a practical scenario.
10. Reflect on what I learned.

Sometimes the code works immediately.

Sometimes it doesn't.

And sometimes a missing bracket or quotation mark becomes the most important lesson of the day.

I am learning to see those moments as part of the process.

This lesson took strings a step further.

### What I Practiced

* Percentage formatting.

### Hands-On Scenarios

I built:

* A student report card.
* A payroll summary.
* An e-commerce order receipt.
* A discount calculation.
* An employee profile generator.

For example:

```python
employee_name = "David Musa"
basic_salary = 185000
bonus = 35000
tax_rate = 7.5

gross_salary = basic_salary + bonus
tax_amount = gross_salary * (tax_rate / 100)
net_salary = gross_salary - tax_amount

print(f"Gross Salary: ₦{gross_salary:,.2f}")
print(f"Tax Amount: ₦{tax_amount:,.2f}")
print(f"Net Salary: ₦{net_salary:,.2f}")
```

### Key Takeaway

This lesson showed me that code should communicate clearly.

The program may calculate the correct answer, but how that answer is presented also matters.

Good formatting makes information easier to understand and easier to trust.

# Case Study Project

## Sales Forecasting Engine

After completing the foundational lessons, I worked on my first case study project.

The goal was to demonstrate how basic Python programming concepts can come together to solve a realistic business problem.

The project simulated a retail business that needed to analyze sales performance and make basic forecasting and inventory decisions.

### The Business Problem

Imagine a retail business that needs to answer questions such as:

* How much revenue did we generate?
* Did we achieve our sales target?
* What could future sales look like?
* Do we need to restock?
* Which products may have higher demand?
* Should we consider promoting a product?

Instead of answering these questions manually, I built a simple Python-based model to demonstrate how these decisions could be automated.

### Concepts Applied

The project brought together concepts I had learned across the lessons, including:

* Variables.
* Data types.
* Arithmetic operators.
* Comparison operators.
* Logical operators.
* Assignment operators.
* String formatting.
* Business logic.

### Example

```python
product_name = "Wireless Mouse"
selling_price = 12500
units_sold = 180
weekly_sales_target = 200
forecast_growth_rate = 15
current_stock = 250
minimum_stock_level = 120
product_available = True

weekly_revenue = selling_price * units_sold

forecast_sales = int(
    units_sold + (units_sold * forecast_growth_rate / 100)
)

forecast_revenue = forecast_sales * selling_price

current_stock -= units_sold

sales_target_achieved = units_sold >= weekly_sales_target

restocking_required = current_stock < minimum_stock_level

promotion_eligible = (
    product_available
    and sales_target_achieved
)

high_demand_forecast = (
    forecast_sales > 200
    or forecast_revenue > 2500000
)
```

### What This Project Taught Me

The biggest lesson from the case study was that individual Python concepts become more meaningful when combined.

Variables store the information.

Arithmetic calculates the results.

Comparison operators evaluate performance.

Logical operators support business decisions.

Assignment operators update changing values.

String formatting communicates the results.

That is the progression I am beginning to understand.

Learning Python is not about memorizing isolated commands.

It is about learning how to combine small building blocks to solve larger problems.
